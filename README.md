## Layout

- `skills/<skill-name>/` contains complete, installable skills.
- `references/` contains instructions shared across skills. `references/t3-code.md` is the shared T3 Code host reference. `references/factory/` holds the T3, GitHub, screenshot, and PR-writing references for the `factory-*` skills.
- Skills that read shared references carry a `shared` symlink to `../../references` and cite paths as `shared/...`. Installers symlink each skill folder, and file tools that normalize `../../references` before opening it look outside this repository. The inner symlink resolves from the skill's real location either way.
- `scripts/` contains project utilities.

## Factory and pr-review-loop

The `factory-*` skills form one system in T3 Code. `factory-start` dispatches work to `factory-dev`, which opens `factory`-labeled PRs. `factory-loop` runs on a schedule on a cheap model. It delegates `factory-review` to Codex as subagent tasks, launches `factory-resolve` threads on Opus, then merges. `factory-review` and `factory-resolve` are Factory-tagged variants of `github-pr-review` and `gh-resolve-pr-comments`.

`pr-review-loop` drives every open PR in a repository instead, and skips PRs with the `factory` label so the two loops never act on the same PR.
