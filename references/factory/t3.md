# T3 Code for Factory skills

Every Factory thread runs in T3 Code. Read [the shared T3 reference](../t3-code.md) for the gate, tool names, calls, model lookup, and launch rules. This file adds the Factory's models and the blocks pasted into child briefs.

## Models

Pick IDs from `orchestrator_capabilities {}` by tier. The examples are not authoritative.

| Thread | Tier | Example | Fallback |
| --- | --- | --- | --- |
| Loop (scheduled pickup) | Cheapest fast Codex tier | `gpt-6-luna`, reasoning `low` | Cheapest fast Claude tier (`claude-haiku-5-5`); state the fallback |
| Dev, Resolve | Newest Opus | `claude-opus-5-5` | Report the blocker |
| Review (delegated task of the loop) | Newest Codex flagship | `gpt-6.1-sol` | Newest Opus; state the fallback |

The loop only reads state, launches children, and runs the mechanical merge gate. Reviews run as `delegate_task` children of the loop, T3's recommended way to mix harnesses. Resolve and Dev run as top-level threads because they write, push, and need T3-bound worktrees. It never reviews, fixes, or writes code; that work goes to the Review, Resolve, and Dev models above. A model the user names wins.

## Reporting block

Append this to every top-level child brief (Dev, Resolve), with the placeholders filled. Delegated tasks skip it; their final answer is the report:

```
Report to your parent's T3 thread when done; never wait to be polled.
Tool: t3_thread_send (Claude Code: mcp__t3-code__t3_thread_send; Codex: mcp__t3_code__t3_thread_send).
  {"threadId":"<parent threadId>","mode":"queue","clientRequestId":"<tag>-done","message":"[<tag>] DONE: ..."}
Use clientRequestId <tag>-done for the first DONE and <tag>-done-<k> for the k-th (after a correction), <tag>-blocked-<k> for the k-th BLOCKED, and <tag>-question-<k> for the k-th QUESTION. Keep each one stable across retries of that report.
Link any PR you open with link_pull_request.
If the T3 tools are not listed, call orchestrator_capabilities once directly. If that fails and T3_ACP_MCP_NODE is set, run:
  ELECTRON_RUN_AS_NODE=1 "$T3_ACP_MCP_NODE" ${T3_ACP_MCP_ENTRYPOINT:+"$T3_ACP_MCP_ENTRYPOINT"} acp-mcp-call t3_thread_send '<json above>'
```

## Delegation block

Append this to every brief whose skill may delegate:

```
Delegate inside your own thread. Never launch top-level threads (no t3_thread_launch or create_threads).
  orchestrator_capabilities {}   # pick providerInstanceId, model, options
  delegate_task {"title":"<role>","role":"research|implementation|review|test|design|general","mode":"async",
                 "target":{"providerInstanceId":"<id>","model":"<model>"},"clientRequestId":"<tag>-<role>-<n>",
                 "task":"<self-contained brief: request, worktree path, branch, scope, acceptance criteria, return shape>"}
  task_status {"taskId":"<taskId>"}   # only when you need the result mid-turn
Native subagent tools are fine when they support the chosen model. Async completions wake your thread; do not poll or spawn watchers. Use a fresh delegate_task for every new assignment or round, with full context; never t3_thread_send to a childThreadId. Subagents report to you. One writer at a time in a worktree.
```
