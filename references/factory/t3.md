# T3 Code for Factory skills

Every Factory thread runs in T3 Code. Threads are addressed by `threadId`. Each top-level thread is bound to one workspace (the project root or a worktree) when it launches.

## Gate and tool names

- Gate: `orchestrator_capabilities {}` must answer. If the T3 tools are not listed, call it once directly before concluding T3 is absent; MCP servers can attach lazily. If T3 is absent, report `<skill> requires T3 Code.` and stop.
- Claude Code: `mcp__t3-code__<tool>` (load deferred schemas with ToolSearch `select:` first).
- Codex: `mcp__t3_code__<tool>`; in code mode `tools.mcp__t3_code__<tool>({...})`.
- ACP fallback, when the tools are missing but `T3_ACP_MCP_NODE` is set:
  `ELECTRON_RUN_AS_NODE=1 "$T3_ACP_MCP_NODE" ${T3_ACP_MCP_ENTRYPOINT:+"$T3_ACP_MCP_ENTRYPOINT"} acp-mcp-call <tool> '<json args>'`

## Quick reference

| Need | Call |
| --- | --- |
| Own location | `t3_thread_configuration {}` → `threadId`, `modelSelection`, `runtimeMode`; `t3_thread_list {limit:1}` → `projectId` |
| Model catalog | `orchestrator_capabilities {}` → `providers[]` with `providerInstanceId`, `canRunChildTask`, `constraints`, `models[].id`, `models[].options` |
| Rename self | `t3_thread_update {action:"rename", title}` |
| Find threads | `t3_thread_list {titleContains}` (fields: `threadId`, `title`, `status`, `model`, `parentThreadId`, `linkedPullRequest`); add `settled:true` for settled threads |
| Thread status | `status` ∈ `preparing`, `queued`, `starting`, `running`, `waiting`, `completed`, `interrupted`, `failed`, `cancelled`, `idle` |
| Read a thread | `t3_thread_read {threadId, view:"messages"}` for final answers and reports; `view:"activity", limit:30` for recent work |
| Launch a thread | `t3_thread_launch {title, workspaceStrategy, modelSelection, interactionMode:"default", message}` → `threadId` |
| Message a thread | `t3_thread_send {threadId, mode:"queue", clientRequestId, message}` |
| Pending questions | `t3_pending_request_list {threadId}` → `t3_pending_request_respond` |
| Flag for the user | `t3_thread_organize {action:"mark_unread", threadId}` |
| Archive | `t3_thread_organize {action:"archive", threadId}` |
| Link a PR | `link_pull_request {url}` (links to the calling thread unless `threadId` is given) |
| Worktree inventory | `t3_worktree_list {query}` → refs and checkout paths |
| Schedules | `schedule_task`, `list_scheduled_tasks`, `update_scheduled_task {scheduledTaskId, ...}`, `delete_scheduled_task {scheduledTaskId}` |
| Delegate | `delegate_task`, `task_status` (see the delegation block) |

`schedule_task` binds runs to the calling thread and inherits its model. A thread can schedule only itself.

## Models

Look up IDs with `orchestrator_capabilities {}` each session; do not trust the examples. A provider is usable only if `canRunChildTask` is true and `constraints` is empty. Claude is `claudeAgent`; Codex is `codex`.

| Thread | Default | Fallback |
| --- | --- | --- |
| Loop, Dev, Resolve | Newest Opus (example `claude-opus-5-5`) | Report the blocker |
| Review | Newest Codex flagship (example `gpt-6.1-sol`) | Newest Opus; state the fallback |

A model the user names wins. Never switch provider families silently.

`modelSelection`: `{"instanceId":"<providerInstanceId>","model":"<model id>","options":[{"id":"<option id>","value":"<value>"}]}`. Omit `options` for model defaults. `delegate_task.target` takes the same fields as `providerInstanceId`, `model`, `options`.

## Launching threads

- `t3_thread_launch` has no retry key. Keep the returned `threadId`. If a call errors or its response is lost, check `t3_thread_list {titleContains:"<title>"}` before retrying.
- `interactionMode:"default"`; plan mode stops at a plan.
- Omit `runtimeMode` so the child inherits yours. `t3_thread_send` refuses a target whose permissions are broader than the caller's.
- Omit `projectId` to use your own project.
- `workspaceStrategy`: `{"type":"root"}` for the project checkout; `{"type":"worktree","baseRef":"<ref>","branch":"<new branch>","startFromOrigin":<bool>}` for a new worktree. Omitting it means root.
- Never tell a thread to `git worktree add` or `cd` elsewhere. That does not move its T3 binding. Say the thread is already an isolated worktree and must use it.
- The `message` is delivered after workspace preparation. Confirm the launch with one status check and, if it is not working, one activity read. Never create a duplicate.

## Reporting block

Append this to every child brief, with the placeholders filled:

```
Report to your parent's T3 thread when done; never wait to be polled.
Tool: t3_thread_send (Claude Code: mcp__t3-code__t3_thread_send; Codex: mcp__t3_code__t3_thread_send).
  {"threadId":"<parent threadId>","mode":"queue","clientRequestId":"<tag>-done","message":"[<tag>] DONE: ..."}
Use clientRequestId <tag>-done for DONE, <tag>-blocked-<k> for the k-th BLOCKED, and <tag>-question-<k> for the k-th QUESTION. Keep each one stable across retries of that report.
Link any PR you open with link_pull_request.
If the T3 tools are not listed, call orchestrator_capabilities once directly. If that fails and T3_ACP_MCP_NODE is set, run:
  ELECTRON_RUN_AS_NODE=1 "$T3_ACP_MCP_NODE" ${T3_ACP_MCP_ENTRYPOINT:+"$T3_ACP_MCP_ENTRYPOINT"} acp-mcp-call t3_thread_send '<json above>'
```

## Delegation block

Append this to every brief whose skill may delegate:

```
Delegate inside your own thread. Never launch top-level threads (no t3_thread_launch or create_threads).
  orchestrator_capabilities {}   # pick providerInstanceId, model, options
  delegate_task {"title":"<role>","role":"research|implementation|review|test|design|general","mode":"async",
                 "target":{"providerInstanceId":"<id>","model":"<model>"},"clientRequestId":"<tag>-<role>-<n>",
                 "task":"<self-contained brief: request, worktree path, branch, scope, acceptance criteria, return shape>"}
  task_status {"taskId":"<taskId>"}   # only when you need the result mid-turn
Native subagent tools are fine when they support the chosen model. Async completions wake your thread; do not poll or spawn watchers. Use a fresh delegate_task for every new assignment or round, with full context; never t3_thread_send to a childThreadId. Subagents report to you. One writer at a time in a worktree.
```
