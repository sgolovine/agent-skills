# Issue 9 verification checklist

Use this list after you apply `issue-9-rules.md`. Examine all editable text, not only a sample.

## Source and scope

- [ ] Make sure that the standard is the official ASD-STE100 Issue 9 standard.
- [ ] Identify the applicable publication specification, style guide, and official directive.
- [ ] Identify the approved project or subject-field terminology.
- [ ] Mark each passage as procedural text, descriptive text, a note, or a safety instruction.
- [ ] Do not change facts, requirements, safety meaning, or normative strength.
- [ ] Keep protected code, identifiers, commands, names, labels, and quoted text unchanged.

## Dictionary audit

Apply this section only to a full-dictionary result.

- [ ] Examine every editable word in the official Issue 9 dictionary.
- [ ] Examine the approved part of speech for each approved word.
- [ ] Examine the approved meaning for each approved word.
- [ ] Examine each verb form and adjective form.
- [ ] Apply all restrictions and help in each applicable entry.
- [ ] Use an alternative only when it keeps the meaning and correct grammar.
- [ ] Change the sentence construction when a direct replacement is not sufficient.
- [ ] Examine each unapproved word as a possible technical noun or technical verb before replacement.
- [ ] Examine each word that is not in the dictionary as a possible technical noun or technical verb.
- [ ] Make sure that each technical term agrees with approved project terminology.
- [ ] Apply Rule 1.9 or 1.12 when no approved project term exists.

For a rules-only result, mark all dictionary-dependent items as not examined. Do not claim a full audit.

## Words and terminology

- [ ] Use only approved words, applicable technical nouns, and applicable technical verbs. (1.1)
- [ ] Use approved words only with their approved parts of speech. (1.2)
- [ ] Use approved words only with their approved meanings. (1.3)
- [ ] Use only approved verb and adjective forms. (1.4)
- [ ] Make sure that each technical noun fits an eligible category and context. (1.5, 1.6)
- [ ] Do not use a technical noun as a verb without correct dual classification. (1.7)
- [ ] Use the approved field term. (1.8)
- [ ] Make each new technical noun short, clear, and necessary. (1.9)
- [ ] Remove regional language, slang, and jargon. (1.10)
- [ ] Use one technical noun for one item. (1.11)
- [ ] Make sure that each technical verb fits a Rule 1.12 subcategory and its applicable context. (1.12)
- [ ] Use an approved verb when approved words can give the same sentence. (1.12)
- [ ] Do not use a technical verb as a noun without a permitted exception. (1.13)
- [ ] Use the required spelling and do not change immutable quoted spelling. (1.14)
- [ ] Use no more than three words in an ordinary multi-word noun. (2.1)
- [ ] Introduce and control each long official technical noun correctly. (2.2)

## Verbs and sentences

- [ ] Use only dictionary-listed verb forms. (3.1)
- [ ] Use only the permitted forms and simple tenses. (3.2)
- [ ] Use a listed past participle only as an adjective. (3.3)
- [ ] Remove perfect, progressive, and complex passive constructions. (3.4)
- [ ] Use an `-ing` form only as permitted. (3.5)
- [ ] Use active voice, except when Rule 3.6 permits passive voice. (3.6)
- [ ] Use a direct approved verb for each action. (3.7)
- [ ] Make each sentence short, clear, concrete, accurate, and unambiguous. (4.1)
- [ ] Keep every necessary subject, noun, verb, article, and antecedent. (4.2)
- [ ] Remove contractions. (4.2)
- [ ] Apply all structure and punctuation controls to vertical lists. (4.3)
- [ ] Connect related sentences with approved words or phrases. (4.4)
- [ ] Use articles and demonstrative adjectives correctly. (4.5)

Search editable prose for contractions, perfect constructions, progressive constructions, and semicolons. Review each match in context.

## Procedures and notes

- [ ] Keep each procedural sentence at 20 words or fewer. (5.1)
- [ ] Give one instruction in each sentence unless actions occur at the same time. (5.2)
- [ ] Show the work-step sequence clearly. (5.2)
- [ ] Put an immediate result or limit directly after its related action. (5.2, 5.5)
- [ ] Write each instruction in the imperative. (5.3)
- [ ] Use `must` only in the restricted procedural context. (5.3)
- [ ] Put each necessary prerequisite condition before its command. (5.4)
- [ ] Put a comma between that condition and command. (5.4)
- [ ] Use notes only for descriptive information. (5.5)
- [ ] Keep instructions, requirements, limits, tolerances, results, and safety text out of notes. (5.5)
- [ ] Remove the notes and make sure that the procedure remains full. (5.5)

Do not flag every mid-sentence `if` or `when`. Rule 5.4 applies to a prerequisite for a procedural command.

## Descriptions

- [ ] Keep imperatives out of descriptive text.
- [ ] Give information gradually and use one subject in each sentence. (6.1)
- [ ] Use consistent key words, key phrases, and logical connections. (6.2)
- [ ] Keep each descriptive sentence at 25 words or fewer. (6.3)
- [ ] Group related information in paragraphs. (6.4)
- [ ] Start each paragraph with a topic sentence. (6.4)
- [ ] Give one topic in each paragraph. (6.5)
- [ ] Read the topic sentences as an outline and make sure that the sequence is logical. (6.5)
- [ ] Keep each paragraph at six sentences or fewer. (6.6)

## Safety instructions

- [ ] Do an applicable risk analysis. (7.1)
- [ ] Use the correct risk word or symbol. (7.1)
- [ ] Use a warning for injury, death, or combined injury and damage risk. (7.1)
- [ ] Use a caution only for damage to objects. (7.1)
- [ ] Follow the applicable publication format. Do not treat uppercase text as an STE requirement. (7.1)
- [ ] Start with an accurate command or required condition. (7.2)
- [ ] Give the specified risk or possible result when it is available. (7.3)

## Punctuation and word count

- [ ] Use an applicable style guide for punctuation that STE does not control.
- [ ] Remove each semicolon and write separate sentences. (8.1)
- [ ] Use hyphens only for directly related words. (8.2)
- [ ] Do not use a dash as a hyphen. (8.2)
- [ ] Use parentheses only for a permitted purpose. (8.3)
- [ ] Count the vertical-list lead-in as a sentence that ends at the colon. (8.4)
- [ ] Count each vertical-list item as a new sentence. (8.4)
- [ ] Count parenthetical text as one word in its containing sentence. (8.5)
- [ ] Also count the parenthetical text as a separate sentence. (8.5)
- [ ] Apply all special one-word categories. (8.6)
- [ ] Do not count paragraph and work-step identifiers. (8.6)
- [ ] Count each applicable hyphenated group as one word. (8.7)
- [ ] Count every sentence with its applicable 20-word or 25-word limit.

## Construction and consistency

- [ ] Restructure each sentence when a direct replacement fails. (9.1)
- [ ] Examine the meaning, grammar, and nearby text after each change. (9.1)
- [ ] Use each approved word correctly. (9.2)
- [ ] Remove unapproved phrasal verbs. Examine restricted approved phrasal verbs. (9.3)
- [ ] Use consistent terminology, wording, and sentence patterns. (9.4)

## General Recommendations

- [ ] Use `that` when it makes a clause boundary clear. (GR-1)
- [ ] Review each use of `with` for ambiguity and keep the primary action verb. (GR-2)
- [ ] Use only approved pronouns and replace ambiguous pronouns with nouns. (GR-3)
- [ ] Make every referent of `this` clear. (GR-4)
- [ ] Examine possible false friends against their English meanings. (GR-5)
- [ ] Replace or remove Latin abbreviations. (GR-6)
- [ ] Use neutral, non-discriminatory, and gender-neutral language. (GR-7)
- [ ] Use possessive forms only when they are correct. (GR-8)

## Delivery

- [ ] Report each finding with an accurate rule or recommendation identifier.
- [ ] Distinguish rules from General Recommendations.
- [ ] State whether the result is rules-only or full-dictionary.
